# Browser reliability diagnostics

Device consent defaults off. Enable “Share browser reliability & speed reports” in Help improve Natalastra or the owner diagnostics page. Events use only strict allowlisted fields. No arbitrary messages, stacks, inputs, user IDs, full URLs or user-agent strings. First-party asset basename and source location aid investigation without leaking query strings. In-memory random session IDs group reports; they are excluded from dashboard responses.

`/diagnostics` is restricted to the configured RESEARCH_ADMIN_EMAIL, using verified server identity. Records are in Supabase `natal_diagnostics`; RLS is enabled with no anonymous/authenticated policies or table grants. Only the server service role has SELECT/INSERT/DELETE. The existing statement registry restricts the database RPC. The same schema runs in D1 integration tests.

Observer covers global errors, rejected promises, first-party script/style resource errors and React route error boundary errors. Raw messages are classified locally then discarded. Dynamic script basenames vary by release. Error categories deliberately trade stack detail for privacy. This is not a remote replay tool or full exception stack tracker.

web-vitals hooks are registered once per document after consent: LCP, INP, CLS, TTFB. Values can describe the current document before consent; reports send only while consent is enabled. Event Timing click samples >=16ms show browser event duration, not async completion. Shared apiFetch measures headers/status or rejection, not body download/render completion; direct fetch/OAuth redirect requests are outside this instrumentation. Workspace navigation records two requestAnimationFrame callbacks, not a guaranteed content-complete paint. Slow actions have explicit action markers where useful. Missing samples do not prove successful buttons; no reliability success rate is fabricated.

Queue: max100 events/document, 20/request, five-second flush plus pagehide/hidden; keepalive fetch, no retries, network reporting cannot block an action. Strict request size, same-origin/custom-header CSRF, max10 batches/session/rolling day and global best-effort1000 batches/day. Concurrent insert races can slightly exceed limits; this is bounded sampling, not a DDoS firewall. Errors deduplicate within each pending batch. Withdrawal clears unsent reports, not already anonymous stored records.

30-day cleanup occurs when the diagnostics endpoint is used; no background purge scheduler. Owner dashboard summarizes latest500 batches (max10000 events), latest100 events, p75 of that sample. INP/CLS observers can produce more than one sample/document after page visibility lifecycle changes; metrics are samples, not unique visitors. No alerts, replay, CrUX comparison or real-browser verification is claimed. Unit privacy tests and built-worker auth/validation/caps/retention checks cover the implementation; real device testing remains necessary to establish population performance.
