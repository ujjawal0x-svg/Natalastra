# Natalastra payment activation

Paid checkout is implemented but deliberately disabled in the current complimentary edition. No merchant secrets are stored in the source. Configure runtime environment values through the Site's protected environment settings:

- `LEMON_API_KEY` (secret)
- `LEMON_WEBHOOK_SECRET` (secret)
- `LEMON_STORE_ID`
- `LEMON_DOSSIER_VARIANT_ID` ($14 USD one-time, published)
- `LEMON_PASS_VARIANT_ID` ($39 USD one-time, published; 12-month application access, manual renewal)
- `LEMON_TEST_MODE` (`true` until the complete test succeeds; `false` for live payments)
- `NATALASTRA_PAID_ENABLED` (`true` only for an intentional launch)

Configure the provider webhook for `order_created` and `order_refunded`, with endpoint `/api/billing/webhook`. Validation uses HMAC-SHA256 over the unmodified raw request bytes. No browser query parameter or local flag grants access. An order must match a server-created checkout intent, store, variant, price, currency, mode and payment status. Test purchases never grant live entitlements. A full refund revokes the order; partial refunds retain access. Retries do not create duplicate grants; late paid events cannot undo a refund. A pass expires after 12 months but its included dossier remains available. Clearing the personal journal/archive preserves payment entitlements.

## Private Site delivery

This Site currently keeps its existing private audience. A direct external webhook must not bypass or weaken that access policy. Use an authorized HTTPS relay that stores the Site service-access bearer credential as a server secret, forwards the exact raw webhook bytes and `X-Signature`, and supplies `OAI-Sites-Authorization: Bearer <service-access token>` only to this Site. Do not embed a service token in a URL, frontend bundle or this repository. Alternatively, change hosting/access only with the owner's explicit decision and a reviewed public endpoint.

The application refuses live checkout until a signed test order has been processed for a configured product. This verifies a delivery path before money can be collected. Merchant configuration alone is not enough.

## Prelaunch verification

1. With merchant test mode enabled, create a checkout from a signed-in account.
2. Complete test payment; confirm the raw signed webhook reaches the route and the account shows a test purchase (no live unlock).
3. Test a refund, webhook retry, and return from checkout. A redirect alone must not confirm payment.
4. Verify live-mode prices and billing terms, then deliberately enable launch. Confirm one real end-to-end purchase and cross-device access before promotion.
5. Invite real testers through Site access settings. Real usefulness and return-usage evidence cannot be generated by code alone.

Local regressions: `node tests/quality.mjs`, build via the Sites build helper, `node tests/business-worker.mjs`, `node tests/studio-worker.mjs`. The business suite uses a mock payment transport and isolated local D1 only; it is not proof of a live merchant connection.

## Pricing and operating-cost controls

The shared application catalog in `lib/pricing.ts` uses $14 for a dossier and $39 for a 12-month manual-renewal pass. USD base prices exclude applicable buyer taxes, shown before payment. Provider products must match these amounts before a checkout can open. Historical orders still use their stored checkout-intent price, so a price update does not invalidate their payment or refund notifications. No live merchant configuration was altered by this price update.

Official US benchmarks checked 2026-10-10: The Pattern Go Deeper+ $83.99 annually (US App Store); CHANI Premium $107.99 annually (official help); Co-Star Pro-Star $8.99 monthly (US App Store). Feature bundles and regional prices differ. Natalastra's launch positioning is an inference from these benchmarks and the smaller current product, not evidence of willingness to pay.

Owner-only Access-page calculator models provider transaction fees on the tax-inclusive buyer total, payout charges, a refund/dispute reserve, service cost, support, acquisition and fixed overhead. Defaults are explicit planning assumptions (20% buyer tax, 8% variable transaction fee, $0.50 fixed fee, 3% payout allowance, 5% reserve, 50% contribution target), not actual expense records. Operating costs start blank and must be entered to show margin and break-even results. Paid-user variable service cost must include an allocation for free-user operations. For annual passes, use full-year service and support costs; renewals are voluntary, so do not assume a second-year purchase to justify acquisition spend. Currency conversion, taxes on the business's income and exceptional disputes can add costs outside this model. Nothing guarantees a loss-free business.

New neural synthesis is limited to 20 successful readings per signed-in account per UTC day. Prepared audio replays and device voice remain free. Failed provider synthesis releases the successful-reading reservation; at most 40 synthesis attempts per UTC day prevent unlimited failing retries. Operational counts use a 30-day window, with older rows purged on the next narration request, contain no reading/audio content, and are included in the account export; clearing the personal archive does not reset operational safety counters. This limits automated resource consumption but is not a hosting-cost guarantee.

Feedback storage: `natal_product_feedback` stores explicitly submitted comments/ratings; `natal_research_events` stores optional counts used for a 90-day analytics window, with older rows purged when activity endpoints are used; `natal_research_consent` stores the opt-in preference. Private reflection payloads remain in `natal_reflections`. Production uses Supabase PostgreSQL in project nftpehdlqofukylqtsgy. The historical D1 copy is retained for migration recovery and is not read or written while NATALASTRA_DATABASE=supabase. The research owner dashboard reads only shared comments and opted-in aggregate ratings, excludes the owner's test activity, and does not expose private reflection/journal notes. Account exports include research data. Users can delete submitted feedback, withdraw usage consent or clear their personal archive.
